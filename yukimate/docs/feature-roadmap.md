## 1. このブランチで実装したもの

### Apple 審査 Guideline 1.2（必須）
- **サインアップの同意チェック**：新規登録でチェックを入れるまで送信不可。規約・プライバシーポリシーへのリンク付き。同意日時と規約の版（`terms_accepted_at` / `terms_version`）を auth の user metadata に記録。
- **利用規約 第4条の2**：不適切なコンテンツ・迷惑行為のゼロトレランス、通報・ブロック、24時間以内の確認と削除・利用停止を明記。
- **通報ボタン**：ゲレンデ投稿（既存の「…」）に加え、**他人のプロフィール**（ヘッダーの旗）と**イベント詳細**（ヘッダーの旗、主催者以外）に追加。理由は共通（不適切／スパム／嫌がらせ・迷惑行為／危険／その他）。`src/components/ReportSheet.tsx`。
- **ブロック**：既存（プロフィールのヘッダー）。

### イベント
- **主催者によるメンバーの強制退会**：参加者一覧の「…」→「このイベントから外す」→確認。`left_at` を入れ（チャットからも外れる）、申請を `rejected` にして再申請を止め、本人にプッシュ通知。
- **アクティビティのラベル**：スキー／スノーボード／バックカントリー／パーク／パウダー／ゲレンデクルーズ／スプリットボード（4つまで）。作成画面で選択、イベント詳細に表示、さがすで絞り込み。値の一覧は `src/constants/activities.ts`。

### 天気
- **お気に入りゲレンデの天気**：ホームの天気の下「お気に入りゲレンデの天気 ›」→ ホーム＋♡のゲレンデを一覧（天気・気温・新雪・明日の降雪・3日間の降雪・風）。「雪が多い順」の並べ替え、下に引っ張って更新、タップでゲレンデの予報。♡ の追加は右上から。

### 改善
- **チュートリアル**：初回だけ5枚（ホーム／さがす／作成／チャット／安全）。設定の「使い方をもう一度見る」で再表示。

## 3. 重いので段階を踏むもの（実装までの道のり）

### 3-1. イベントをマップで表示 ／ 集合場所をピンで指定
**重い理由**：地図はネイティブモジュール（`react-native-maps`）で、開発ビルドの作り直し・Google Maps の API キー（Android）・課金設定が要る。

1. **スキーマ**：`posts_events` に `meeting_lat double precision`, `meeting_lng double precision`（任意）。`resorts.latitude/longitude` は既にある。
2. **依存**：`npx expo install react-native-maps`、`app.json` に Android の `googleMaps.apiKey`（EAS secret）。iOS は Apple Maps で可。→ **dev client の再ビルドが必要**。
3. **集合場所のピン**：作成画面の「集合場所」の下に「地図で指定」→ 全画面の地図（初期位置はゲレンデの座標）→ 中央ピンを動かして決定。文字の集合場所はそのまま残す。
4. **マップ表示**：さがすの「リスト／スワイプ」に「マップ」を追加。ゲレンデごとにまとめたピン（件数バッジ）→ タップで下からイベント一覧。まずは**ゲレンデの座標でまとめる**（集合場所が無いイベントでも出せる）。
5. **詳細**：イベント詳細に小さな地図＋「マップで開く」（`Linking` で Google/Apple Maps）。
- 目安：3〜5日（ビルド・キー発行を除く）。

### 3-2. テーマ別チャンネル（誰でも開設）＋ チャンネルタイプ
**重い理由**：新しいテーブル・RLS・リアルタイム・モデレーションが一式要る。

1. **スキーマ（案）**
   - `channels(id, owner_user_id, name, description, kind text CHECK (kind IN ('chat','media_only','reaction_only')), resort_id NULL, is_public bool, created_at, archived_at)`
   - `channel_members(channel_id, user_id, role text CHECK (role IN ('owner','moderator','member')), joined_at, muted_until)`
   - `channel_posts(id, channel_id, user_id, body NULL, media jsonb, created_at, deleted_at)` — `media_only` は body を禁止（CHECK はアプリ＋トリガーで）
   - `channel_reactions(post_id, user_id, emoji)`（`reaction_only` はコメント不可・リアクションのみ）
2. **RLS**：公開チャンネルは誰でも閲覧、投稿はメンバーのみ、削除は本人・owner・moderator。
3. **UI**：チャットタブを「イベント」「チャンネル」の2つに分ける（イベントチャットとは別枠）。チャンネル一覧（参加中／見つける）→ 作成（名前・説明・タイプ）→ 画面はタイプ別（通常チャット／画像グリッド／リアクションだけのフィード）。
4. **モデレーション**：投稿の通報（`reports.target_type` に `'channel_post'` を追加）、owner による削除・追放、開設数の上限（1人3つ等）。
5. **リアルタイム**：既存のイベントチャットと同じ Supabase Realtime の購読を流用。
- 目安：1.5〜2週間。**先にモデレーション（3-4）の土台を作るのがおすすめ**（誰でも開設できる場は荒れやすく、審査でも見られる）。

### 3-3. コミュニティ拡張（レーティング・ユーザー評価・おすすめ情報・スキー場インフォメーション）
1. **ゲレンデのレーティング入力**：`resort_ratings(category, score)` と `resort_rating_summary` は既にある。ゲレンデページの「評価」タブに入力シート（カテゴリごとに★）を付け、1人1カテゴリ1件（upsert）。集計はビュー or トリガー。→ **小さめ（1〜2日）、次にやる候補**。
2. **ユーザー評価**：イベント終了後の評価タイムは実装済み。集計の見せ方は 2 章の表。
3. **おすすめ情報**：ゲレンデ投稿に「おすすめ」種別（ごはん・温泉・コース・駐車場）を足し、ゲレンデページにタブ or セクション。`feed_posts.kind` の追加で済む。
4. **スキー場インフォメーション**：リフト運行・営業時間・料金はデータソースが必要（公式サイトの手入力 or 提携 API）。まずは `resorts` に `official_url`, `season_start`, `season_end`, `night_skiing bool` などの静的情報を足して表示。
- 目安：1 が 1〜2日、3 が 2〜3日、4 はデータソース次第。

### 3-4. 通報の充実（ユーザー監視・運営側）
**今**：アプリから `reports` に入るだけ。**運営の見る場所が無い**。

1. **自動の一時非表示**：同じ対象への未対応の通報が N 件（例 3件・別々の人）を超えたら、対象の投稿を `hidden_at` で隠すトリガー。
2. **運営ダッシュボード**：Supabase Studio のビューで始める（`reports` × 対象の中身 × 通報者数）。次に簡単な管理画面（Next.js + service role、または Retool）。
3. **対応フロー**：`reports.status`（pending → reviewing → resolved / rejected）、`moderation_actions(target, action, reason, actor, created_at)` で履歴。利用停止は `users.suspended_until` を見て、ログイン時・投稿時に弾く（RLS でも）。
4. **24時間以内の確認**（規約で約束した）：新しい通報で運営の Slack / メールに通知（Database Webhook → Edge Function）。
5. **コメントの通報**：`feed_comments` は表があるが UI が無い。コメント UI を作るときに「…→通報」を同時に入れる（`ReportSheet` の `targetType="comment"` で使える）。
- 目安：1・4 で 1〜2日（**審査前に 4 だけでも入れておくのが安全**）、2・3 で 3〜5日。

### 3-5. リーダーボード（参考程度）
1. **何を数えるか**：シーズン中の「参加したイベント数」「主催したイベント数」「参考になった数」。滑走距離は計測手段が無いので対象外。
2. **集計**：`leaderboard_season` マテリアライズドビュー（1日1回 refresh、pg_cron）。
3. **見せ方**：ゲレンデページに「このゲレンデのよく滑る人」トップ5、プロフィールに順位バッジ。**ランキングを見せたくない人のためにプロフィール設定で除外できるように**。
- 目安：2〜3日。競争要素は荒れやすいので、3-4 の後がおすすめ。
