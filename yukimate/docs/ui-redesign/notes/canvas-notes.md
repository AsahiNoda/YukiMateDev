# UIレビュー キャンバスの付箋（原文）

キャンバス「Slope Link UIレビュー（現状コード再現）」に貼った付箋をそのまま書き出したもの。✓ が付いた項目はAsahiが決定済み。

## 全画面共通

### 全画面共通の課題

1. タブが6個・アイコンのみ。Explore（虫眼鏡）とDiscover（コンパス）の違いが伝わらない。現在地は4pxの点だけ
2. 「作成」はタブから隠され、ホームに＋が2つ（投稿／イベント作成）
3. ★が「保存」「★登録ユーザー」「Discoverの保存」の3つの意味で使われている（ホームの保存はブックマーク）
4. スレートブルー #5A7D9A の文字は背景上で3.3〜3.8:1（基準4.5未満）。白文字ボタンも4.3:1
5. 文言の直書き：カード内「イベント/無料/保存」、Snowfeed「Resort Ratings」、Discover「Like/Star」、チャット「Today/Upcoming」→ 英語UIで崩れる
6. #FFFや暗い影が前提なのに app.json は automatic → ライトモードで崩れる可能性
7. spacing.ts / colors.ts があるのに数値の直書きが多い。角丸が10/12/16/18/24と混在、平面の文字にもtextShadow

### 色と形のルール案

・文字用のティント #8FB3D1（暗い背景で6.4:1）
・主要ボタン：#8FB3D1地＋紺文字（7.4:1）
・ゴールドは価格と★登録ユーザー専用
・保存＝ブックマーク、★＝ユーザー、に意味を固定
・角丸はカード12／チップ999の2種類
・textShadowは写真の上の文字だけ

## 現状の課題（画面別）

### ホーム

・見出しは「注目の投稿」だが中身はイベント。カードに日付がない
・天気カードがSnowfeedと重複。赤い「LIVE」は配信中に見える
・クイックアクション（保存/マイ投稿/作成）が一等地を使っている
・右上＋は投稿モーダル、「作成」はイベント作成で「作る」が2系統
・ホームゲレンデ未設定時は文言だけでボタンがない（goToSnowfeed の訳語は用意済み）

### Explore

・上部に中身のないヘッダー（スペーサーだけ）
・カード1枚が約430pxで、1画面に1.5枚しか見えない
・ホスト名18px太字がタイトル20pxと競合
・画像の四隅にバッジが散らばる（カテゴリ・人数・レベル・★）
・日付が「12月20日」のみ（曜日・時刻なし）
・並び替えが右下のFAB。Snowfeedの右下FABは「投稿」で意味が違う
・上級＝エラー色の赤

### Discover

・右スワイプ＝参加申請、左＝保存、上＝スキップ。よくある「左＝見送り」と逆で誤操作しやすい
・毎回のスワイプで確認モーダル → テンポが止まる
・ボタン「Like」が申請、「Star」が保存。ラベルと意味がずれている
・レベルが beginner など生の値で表示される
・コードで気になった点：ボタンは onSwipe('right', event.id) とIDを渡すが、受け側は event オブジェクトを想定している

### Snowfeed

・ヘッダーの🔁（ホームゲレンデ変更）アイコンの意味が伝わりにくい
・Resort Ratings / Overall / Powder… が英語固定
・天気はホームと重複し、ホームとの役割分担があいまい
・右下の投稿FABがタブバーのすぐ上

### チャット一覧

・全行に赤太字「⚠️ 投稿は一定時間後に自動で削除されます」→ 警告に慣れて読まれなくなる。「投稿」と「チャット」の言葉も不一致
・Today / Upcoming / Earlier が英語固定
・80px画像＋参加者＋スキー場＋警告＋プレビューで1行が重い
・リクエストのバッジは良い。タブバーにも申請数を出したい

### イベント詳細

・情報グリッドがアイコン＋値のみでラベルなし（価格と集合場所の区別が文脈頼み）
・説明文が日時・場所より先に来る
・固定フッターでホストと申請ボタンが横並びになり、ボタンが狭い

### イベントチャット

・固定ヘッダー（画像・タイトル・参加者・説明2行・詳細リンク）が約250px。キーボードが出ると会話がほぼ見えない
・既知バグの原因候補：KeyboardAvoidingView が Android で behavior=undefined、iOS は offset=90 固定 → Androidは入力欄が隠れ、iOSは隙間
・ホスト名の緑 #22c55e は開発者バッジと同じ色

### プロフィール

・名前が900ウェイト・大文字・字間1.5で強すぎる
・タグが #INTERMEDIATE #FREERIDE と生の値を大文字化
・見出し（評価・自己紹介…）が日本語固定
・メダル絵文字🥇🥈🥉
・「軽いつながり」の思想に対し、高評価％が上の方で目立つ → 信頼の目安としての見せ方を検討

## 改善案（画面別）

### ホーム改善案

・✓ 決定：ヘッダーのゲレンデ名を削除し、アプリ名「Slope Link」を表示（4画面とも）。Snowfeedへは天気カード下部の「ゲレンデ情報・投稿を見る」から
・タブを5つにしてラベルを付ける（ホーム／さがす／作成／チャット／マイページ）
・Snowfeedの天気・投稿はホームの「ゲレンデ」部分へ統合
・天気カードは現状のデザインを維持（ガラス調カード＋山の背景）
・✓ 採用：ホームゲレンデで開催中・開催予定のイベントを特集（「今週末、白馬八方尾根で滑る人」）。カードは今の写真付きスタイルで、日付を追加

### ホーム追加要素の案（予定あり・スクロール全体）

・天気カードを横スライドに。1枚目＝天気、2枚目＝次の予定（参加確定イベントがあるときだけ2枚目を追加）。下のラベル付きドットで切替。あと◯日、日時・集合・メンバー、チャット（新着数）と詳細
・申請ステータス：「あなたの申請 返事待ち」と「届いたリクエスト」を2枠で。届いた方はホスト向けにオレンジ枠で目立たせる。0件の枠は出さない
・パウダーアラート：+20cm以上の予報で「ゲレンデの今」フィードの先頭に。「朝イチ組を作る」で作成画面へ（日時を翌朝で入力済みに）
・リフト運行：天気カードの下段に「9/11運行中」＋運休理由。タップで一覧
・週間の雪予報：7日分の棒グラフ。週末を枠で強調、最大降雪日をアクセント色
・あなたに合いそう：プロフィールのレベル／スタイルと一致するイベント。理由を見出し下に明記
・混雑サマリーは実装が現実的でないため見送り
・運休はアンバー＋文字で示す（色だけに頼らない）

### 予定がないときのホーム

・「次の予定」の位置に、点線枠の入口カードを出す
・「今週末・一人参加OK・ホームゲレンデ」で絞った件数を表示し、その条件のまま「さがす」タブへ
・該当0件なら「自分で作る」を主ボタンにする
・届いたリクエストが0件なら、申請の枠は自分の申請だけ

### さがす（リスト）改善案

・DiscoverとExploreを1タブにまとめ、右上でリスト／スワイプを切替
・✓ 決定：写真が主役の今のカードのスタイルを維持
・写真の上に日付（12/20（土）8:30）とレベル、右上に保存
・ホスト名は小さくしてタイトルを主役に。写真は176pxで、1画面に約2件
・並び替えはフィルター行の中へ（FAB廃止）
・「空き2」「一人参加OK」を文字チップで
・✓ スワイプで見送ったかどうかに関係なく全件を表示

### さがす（スワイプ）改善案

・✓ 決定：この改善案のデザインで進める
・✓ 決定：スワイプで見送ったイベントも、リストには常に表示する（スワイプの束から外すだけ）
・左＝スキップ、右＝気になる（保存）
・参加申請はボタンだけ＝重い操作は意図して押す
・確認モーダルは申請のときだけ
・下部に3ボタン＋ラベル

### イベントチャット改善案

・ヘッダーを1行（タイトル＋日時）に圧縮、タップで詳細
・削除までの残り時間は控えめなバーで1か所だけ
・入力欄はキーボード直上（Android は behavior="height"、または react-native-keyboard-controller）

### マイページ改善案

・✓ 決定：設定はマイページ右上の「設定」ボタンから別画面へ遷移（マイページの下には並べない）。ホーム右上の歯車は削除（ホーム改善案4画面とも）
・マイページ＝自分のプロフィールだけ。「プロフィールを編集」はボタンとして独立、「相手からの見え方」で公開プロフィールを確認
・名前は通常の太字（大文字・字間広げをやめる）、タグは日本語チップ、メダル絵文字→1・2・3
・高評価%の代わりに「参加・主催・また滑りたい」の実績を控えめに

### 設定（別画面）

・左上の戻るでマイページへ。タブバーは出さない（スタック遷移）
・グループ：アカウント／通知／表示／プライバシーと安全／サポート
・ホームゲレンデ変更、パウダーアラートの基準もここから
・アカウント削除は最下部、赤い文字だけ
・Playで「設定」⇄「戻る」の遷移を試せます

### Snowfeedの位置づけ（提案）

・タブには置かない。ホームは「ホームゲレンデの今日」、Snowfeedは「どのゲレンデでも見られる詳しいページ」と役割を分ける
・入口は5か所（ホームは天気カード下部のリンク）。どこから来ても同じ画面で、開くタブだけ変える（予報か投稿か）
・ホームの天気・週間予報はダイジェスト、Snowfeedは全部入り
・通知（パウダーアラート）から直接投稿タブへ → 朝イチ組の作成につなげる

### Snowfeed改善案

・ヘッダーのゲレンデ名タップで切替。下にお気に入りゲレンデのチップ（ユーザー要望：毎回選ぶのが手間）
・🔁アイコンは廃止。ホームゲレンデは「ホーム」チップで表示、変更は設定から
・✓ 天気カードはホームと同じ案D（今の状態1行＋時間ごとの予報）。下にリフト運行、「7日間の予報」で予報タブへ
・ページ内タブ：投稿／予報／評価。評価は日本語に（パウダー・カービング…）
・投稿は写真が主役。場所タグ（リーゼン上部など）と「参考になった」
・各投稿の「…」に通報（Apple審査 1.2 の未対応分）
・「このゲレンデのイベント」帯でイベント参加へ戻す
・投稿ボタンは右下の丸から、下部の文字付きボタンへ

## ホームの天気カードの見せ方（4案）

**✓ 決定：案D を採用**（2026-11-17）。ホームは `mockups/New-Home-Weather.html`、Snowfeedも同じ案Dに統一（`mockups/New-Snowfeed.html`）。案A〜Cは不採用だが、検討の経緯として残す。

### 案A：写真ヒーロー

・ゲレンデの写真を全面に。気温を76pxの細字で大きく
・新雪・風速・視界はガラス調の3つの枠に
・天気アプリらしい華やかさ。ゲレンデごとの写真の用意が必要
・枠と影を減らし、文字は写真の上だけ

### 案B：新雪が主役

・滑る人が一番気にする新雪を72pxの太字で
・昨日／今日／明日予報の3本の棒で流れが分かる
・15cm以上で「パウダー日」バッジ
・気温などは下段に小さく。データは今のOpen-Meteoで足りる

### 案C：ひとことで判定

・数字の前に「パウダー日和」「上部は風が強め」など結論を出す
・チップで根拠（新雪・気温・リフト・強風）
・おすすめの時間帯つき
・判定ルールを決める必要あり（例：新雪15cm以上＝パウダー日和、風10m/s以上＝強風注意）

### 案D：時間ごとの予報つき

・今の情報は1行に圧縮し、8〜16時の時間ごとの気温と降雪を並べる
・狙い目の時間帯をハイライト
・ユーザー要望「Liveより予報が見たい」に一番近い
・Open-Meteoの時間ごとのデータで実装できる

共通：「LIVE」バッジは配信中に見えるので「8:00 更新」に。視界の「Moderate」は日本語に
