2026年11月のUIレビュー（claude.aiのデザインキャンバス）で決めた改善案を、アプリに実装するための資料です。
このフォルダーだけを読めば実装を始められるように書いています。

```
docs/ui-redesign/
├── README.md               ← この指示書（最初に全部読む）
├── mockups/                ← 改善案の画面（ブラウザで開ける静的HTML、390×844のiPhone想定）
│   ├── index.html          ← 一覧ページ

└── notes/canvas-notes.md   ← キャンバスに貼った付箋の原文（現状の課題＋改善案）
```

## 0. Claude Codeへの進め方の指示

1. 最初に `README.md` と `notes/canvas-notes.md` を全部読む。そのあと、対象画面の `mockups/*.html` を読む。
2. **フェーズ単位で進める**（下の「7. 実装フェーズ」）。1フェーズが終わるごとに止まり、変更点と確認してほしい点を報告する。
3. モックアップは**見た目の仕様**。HTMLの構造を真似るのではなく、既存のReact Nativeコンポーネント・hooks・Supabaseのクエリを活かして再現する。
4. モックの文言・人数・日付・ゲレンデ名は**ダミー**。実データ（hooks）に置き換える。写真のグレーの山の図は画像プレースホルダーなので、実際のイベント画像・投稿画像に置き換える。
5. **データの裏付けがない要素は作り込まない**（MVP優先）。該当箇所は「8. データが必要な要素」を参照し、フラグで非表示にするかTODOコメントを残す。
6. 新しい文言はすべて `src/i18n/translations.ts` の `ja` と `en` の両方に追加する。日本語・英語の直書きは禁止（既存の直書きも、触った画面では移す）。
7. 色・角丸・余白は直書きせず、`src/theme/colors.ts` と `src/constants/theme.ts`、`src/constants/spacing.ts` にトークンとして追加してから使う。
8. Supabaseのスキーマ変更が必要になったら、実装する前に提案して止まる。
9. 「9. 未決定の事項」に当たったら推測で決めず、質問する。

## 1. デザインの基本ルール

### 色（ダークテーマ基準）

| 用途 | 値 | 備考 |
|---|---|---|
| 背景 | `#1A202C` | 既存 `background` |
| カード | `#242B38` | 既存 `cardBackground` |
| 二次背景・チップ | `#2D3748` | |
| 区切り線 | `#374151` | |
| 本文 | `#F7FAFC` / 補助 `#E2E8F0` / 弱 `#CBD5E0` | |
| 無効・ラベル | `#9BA1A6` | |
| **文字用ティント（新規）** | `#8FB3D1` | 暗い背景でコントラスト6.4:1。リンク・選択中タブ・日付に使う |
| **主要ボタン（新規）** | 地 `#8FB3D1` ＋ 文字 `#1A202C` | 7.4:1。今の `#5A7D9A` ＋白文字（4.3:1）を置き換える |
| ゴールド | `#D4AF37` | **価格と★登録ユーザー専用** |
| 成功系チップ | 地 `rgba(16,185,129,0.16)` 文字 `#6EE7B7` | 「残り3人」など |
| 注意系チップ | 地 `rgba(245,158,11,0.16)` 文字 `#FCD34D` | 「残り1人」「混雑」など |
| 削除・危険 | `#FC8181` | アカウント削除の文字だけ |

- `#5A7D9A` を**文字色として使うのはやめる**（背景上で3.3〜3.8:1で基準を満たさない）。
- 状態は色だけで伝えない（例：運休はアンバー色＋「運休」の文字）。

### アイコンの意味の固定

- **保存 ＝ ブックマーク**（イベントの保存）
- **★ ＝ ★登録ユーザー**（人に対してだけ使う）
- 今は★が「保存」「★登録ユーザー」「Discoverの保存」の3つの意味で使われているので統一する。

### 形・文字

- 角丸は **カード12 ／ チップ・ボタン999（ピル型）** の2種類を基本にする（写真が主役の大きいカードは16〜24も可）。
- `textShadow` は写真の上の文字だけに使う。
- タップできる領域は最低44×44。
- フォントはシステムフォントのままでよい（モックはNoto Sans JPで描いている）。

## 3. ホーム

モック：`New-Home.html`（基本形）、`New-Home-Snow.html`（予定ありのときの全体スクロール）、`New-Home-Slide2.html`（上部スライド2枚目）、`New-Home-NoPlan.html`（予定がないとき）
対象：`src/screens/tabs/HomeScreen.tsx`、`src/hooks/useHomeData.ts`

上から順に以下を並べる。

1. **ヘッダー**：✓ **決定：アプリ名「Slope Link」だけを表示する**。ゲレンデ名（▾）と歯車は削除する（ホームのモック4画面すべて）。
2. **天気カード**：✓ **決定：案D「時間ごとの予報つき」**（モック：`New-Home-Weather.html`）。これまでの「今のデザインを維持」は**この決定で置き換える**。
   - 山の背景＋ガラス調のカード（角丸20）は引き継ぐ。
   - 上の行：ゲレンデ名（15px太字）と、右に「● 8:00 更新」（緑の点＋最終更新時刻）。**赤い「LIVE」バッジは廃止**。
   - 今の状態を1行に圧縮：気温（52px・細字）＋「雪 ・ 新雪 18cm」（16px太字）＋「風 4.2 m/s ・ 視界 ふつう」（13px）。視界は「ふつう」など日本語の表示名にする（`Moderate` を出さない）。
   - 「今日の時間ごと」：8時〜16時を2時間刻みで5列。各列に時刻・天気アイコン・気温・降雪量（cm）。
   - 滑るのに良い時間帯の列は、背景を `rgba(143,179,209,0.14)` にして時刻の文字を太字・`#B7D0E4` にする（モックでは8時・10時）。**どの時間をハイライトするかのルールは未決定**（9章）。見出しの右に文字のラベルは出さない。
   - カードの一番下に「ゲレンデ情報・投稿を見る ›」のリンク（Snowfeedの予報タブへ）。
   - データ：Open-Meteo の hourly（`temperature_2m`、`snowfall`、`weather_code`）。`src/services/weatherApi.ts` で取得していなければ追加する。
   - リフト運行の行は、データソースが決まったら時間ごとの行の下に足す（8章）。
   - **注意**：`New-Home.html`、`New-Home-Snow.html`、`New-Home-NoPlan.html`、`New-Home-Slide2.html` の天気カード部分は旧デザインのまま描かれている。**天気カードは `New-Home-Weather.html` を正とし、ほかの要素（スライド、特集、ゲレンデの今など）はそれぞれのモックに従う**。スライド2枚目（次の予定）のカードの高さは、案Dのカードに合わせる。
   - Snowfeedの天気カードも同じ案Dのデザインにする（Snowfeedでは「予報」タブにより詳しい予報を出す）。
3. **横スライド**：1枚目＝天気、2枚目＝次の予定。参加が確定したイベントがあるときだけ2枚目を出す。下にラベル付きのドット（「天気」「次の予定・あと3日」）。
   - 次の予定のカード：あと◯日、日時・集合・メンバー、「チャットを開く（新着数）」「詳細」
4. **申請ステータスの1行**：「申請 返事待ち ◯件 ｜ 届いたリクエスト ◯件」。0件の項目は出さない。
5. **週間の雪予報**：7日分の棒グラフ（新雪cm）。週末を枠で強調し、最大降雪日をティント色に。Open-Meteoの日別降雪量を使う。
6. ✓ **採用：ホームゲレンデのイベント特集**「今週末、◯◯で滑る人」
   - ✓ **写真が主役の大きいカード（240×300）を横スクロール**。今の「注目の投稿」カードのスタイルを維持する。
   - 写真の上に参加人数、右上に保存（ブックマーク）、公式バッジ、下部に**日付（ティント色）**・タイトル・場所。
   - 見出しは「注目の投稿」ではなく、イベントだと分かる文言にする。
7. **あなたに合いそう**：プロフィールのレベル／スタイルと一致するイベント。見出しの下に一致した理由を書く（「プロフィールの『中級』『フリーライド』から」）。`useDiscoverEvents.ts` にあるスタイル一致の処理を流用できる。
8. **ゲレンデの今**：パウダーアラート（+20cm以上の予報のとき先頭に出し、「朝イチ組を作る」で作成画面へ。日時は翌朝で入力済みにする）と、投稿の写真2枚。「投稿を見る」でSnowfeedの投稿タブへ。

**予定がないとき**（`New-Home-NoPlan.html`）
- 次の予定の位置に点線枠の入口カードを出す：「今週末の予定はまだありません／一人参加OKのイベントが◯件」。
- 「◯件をさがすで見る」で、条件（今週末・一人参加OK・ホームゲレンデ）を付けたまま「さがす」タブを開く。0件なら「自分で作る」を主ボタンにする。

**削除するもの**：クイックアクション（保存／マイ投稿／作成）、右上の＋と歯車。
- 保存一覧とマイ投稿はマイページから開けるようにする（場所は質問すること）。

## 6. Snowfeed（ゲレンデページ）

### 画面の構成（上から）
1. ヘッダー：戻る／ゲレンデ名▾（タップで切り替え）／お気に入りのトグル

3. 天気カード：✓ ホームと同じ案Dのデザイン（モック `New-Snowfeed.html`）。ホームとの違いは次の3点
   - 上の行の左は「現在のコンディション」（ゲレンデ名はヘッダーにあるので出さない）
   - 「今日の時間ごと」の右に「7日間の予報 ›」（予報タブへ）
   - 時間ごとの行の下にリフト運行の行（データソース確定後。8章）。「ゲレンデ情報・投稿を見る」のリンクは出さない
4. 「このゲレンデのイベント（今週末◯件・一人参加OK◯件）」の帯 → さがす（そのゲレンデで絞り込み）へ
5. ページ内タブ：**投稿／予報／評価**
   - 投稿：フィルター（すべて／雪質／混雑・リフト／写真のみ）。投稿カードは**写真が主役**で、撮影場所のタグ（リーゼン上部など）、経過時間、「参考になった ◯」、右上の「…」メニュー。
   - **「…」メニューに通報を入れる**（Apple審査 Guideline 1.2 で未対応だった部分）。
   - 予報：7日間の予報（今の `WeatherForecast` を活用）。
   - 評価：今の「Resort Ratings」を日本語化（パウダー／カービング／ファミリー／パーク）。
6. 下部に固定の「ゲレンデの今を投稿」ボタン（文字付き）。右下の丸いボタンは廃止。

- **廃止**：ヘッダーの🔁（ホームゲレンデ変更）アイコン。ホームゲレンデの変更は設定画面から行う。

## 7. マイページと設定

対象：`src/screens/tabs/ProfileScreen.tsx`

### 設定（`New-Settings.html`）
対象：`src/screens/SettingsScreen.tsx`、`app/settings.tsx`、`src/components/settings/*`

- 戻る＋「設定」のヘッダー。グループ分けした一覧：
  - **アカウント**：ホームゲレンデ／言語／メールアドレス・パスワード
  - **通知**：チャットの新着／参加申請・リクエスト／パウダーアラート（基準「+20cm以上」）／イベント前日のリマインド
  - **表示**：テーマ／単位
  - **プライバシーと安全**：プロフィールの公開範囲／ブロックしたユーザー／通報・安全ガイド

## 10. あわせて直すバグ（コードで原因の候補を確認済み）

1. **退会したイベントが一覧に再表示されない**
   `src/hooks/useExplore.ts` と `src/hooks/useDiscoverEvents.ts` が、`event_applications` の `status='approved'` のイベントを除外している。退会したあとも申請が承認済みのまま残る。
   → 除外条件を `event_participants`（`left_at IS NULL`）だけにする。または、退会時に申請の status を `withdrawn` などに更新する（どちらにするか提案してから実装）。
2. **チャットの入力欄の位置ズレ**（Androidでキーボードに隠れる／iOSで隙間）
   `src/screens/EventChatScreen.tsx` の `KeyboardAvoidingView` が、Androidでは `behavior` 未指定、iOSでは `keyboardVerticalOffset` が90の固定値。
   → Androidは `behavior="height"`、iOSはヘッダーの高さ＋セーフエリアから計算する。または `react-native-keyboard-controller` を導入する。
3. **Discoverのボタンにイベントそのものではなくidが渡っている**
   `src/screens/tabs/DiscoverScreen.tsx` のボタンが `onSwipe('right', event.id)` とIDを渡しているが、受け取る側は event オブジェクトを想定している。新しいボタン構成に作り直すときに直す。
4. **Discoverでレベルが生の値で表示される**（`beginner` など）→ 翻訳する。
5. **英語UIで直書きの文言が出る**：Snowfeedの「Resort Ratings」「Overall」、Discoverの「Like」「Star」、チャット一覧の「Today」「Upcoming」「Earlier」、カードの「イベント」「無料」「保存」、プロフィールの見出し。
